# OM-25 CI/CD Ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `main` merge only through Om, only with the other person's approval and green, up-to-date CI, and keep the live GitHub settings provably equal to a checked-in file.

**Architecture:** Repo settings live as data in `.github/settings.json` (rulesets, label, environment, merge options). `scripts/gh_settings.py` (stdlib) normalises live `gh api` output and diffs it against that file; `check` fails closed, `apply --yes` reconciles rulesets/labels. Static kit tests pin the security-relevant values in the file so a weakening edit fails `make kit-check` in CI.

**Tech Stack:** Python 3.12 stdlib, `gh` CLI (Om's own session), GitHub rulesets REST API, GitHub Actions.

**Spec:** card OM-25 (`python3 scripts/board.py show OM-25`), `docs/setup/GITHUB.md`, §19 CI design (`docs/spec/sections/19-*.md`), §21 ways of working (maker/checker, cross-ownership review).

## Decision (Om, 2026-10-28) — replaces the card's "admin bypass for Om's own PRs"

Evidence that drove it (ruleset 25804326 rule-suites): PR #1 (Om's) was merged by Kunal 10 s after his approval → `pass`; PR #5 was merged by Om at 12:21:54 with result `bypass` — the branch was behind after #4, so the admin bypass silently skipped the strict-checks rule.

| ruleset | target | rules | bypass |
|---|---|---|---|
| `main` (25804326, edited) | `~DEFAULT_BRANCH` | deletion · non_fast_forward · pull_request (1 approval, dismiss stale, code owner, **last-push approval**, thread resolution, squash only) · required_status_checks `kit`, strict | **none** |
| `merge-gate` (new) | `~DEFAULT_BRANCH` | update | RepositoryRole 5 (admin), `pull_request` |

Kunal PR → Om approves → Om merges. Om PR → Kunal approves → Om merges. Kunal can never merge. Break-glass (Kunal unreachable on a deadline): Om edits `main` to add himself, merges, reverts, and logs it in GITHUB.md "Break-glass log" — `make gh-check` is red until reverted.

## Global Constraints

- Stdlib only, like the kit (`scripts/board.py`, `scripts/skills.py`); no PyYAML — workflows and dependabot.yml are read line-based.
- Tests: `unittest`, files `tests/kit/test_om_25_*.py`, test names `test_OM_25_*`.
- Branch `om/OM-25-ci-cd`; commits `OM-25 §19 §21: …` ending with the Co-Authored-By line.
- `gh` runs on Om's session; Claude never reads tokens. `gh_settings.py` lists environment secret **names** only.
- Fail closed: any `gh` error, non-admin view (missing `bypass_actors`), or unparsable response → `check` exits 1 with a message; never prints OK.
- Every live settings change (Task 3) is a separate `gh api` call Om approves at the prompt.
- Required checks grow per GITHUB.md §"Required checks"; `kit` is the only job that exists today.

## Review Focus

1. **Bypassing `merge-gate` also bypasses `main`.** Expected: rulesets evaluate independently, so Om merging still needs approval + green strict CI. Pinned by Task 5 V1/V2: the rule-suite for each merge shows `main` = `pass`, only `merge-gate` = `bypass`.
2. **A required check is renamed or deleted** → every merge blocked forever. Pinned by `test_OM_25_required_checks_are_pr_jobs` (Task 2).
3. **`gh-check` run by a non-admin (Kunal) or logged out** → API hides `bypass_actors` / errors. Expected: red with "admin view required", never green. Pinned by `test_OM_25_missing_bypass_field_fails_closed` (Task 1).

5. **A build file lands (OM-01) without a Dependabot entry.** Expected: kit-check red. Pinned by `test_OM_25_dependabot_covers_build_files` (Task 2).

**Interfaces:**
- Produces: `.github/settings.json` shape:
  `{"repo": {"allow_squash_merge": true, "allow_merge_commit": false, "allow_rebase_merge": false, "delete_branch_on_merge": true, "allow_auto_merge": false}, "collaborators": {"omunite215": "admin", "kunalgupta06": "write"}, "labels": ["ai-review"], "environments": {"claude-review": {"branch_policies": ["main"], "secrets": ["CLAUDE_CODE_OAUTH_TOKEN"]}}, "rulesets": [<ruleset>…]}`
  where `<ruleset>` = `{"name", "target", "enforcement": "active", "conditions", "bypass_actors", "rules"}` exactly as the decision table (rules as GitHub's `{type, parameters}`; `main`'s parameters copied from the live ruleset, incl. `require_extra_approval_for_unattributed_changes: true`).
- Produces in `scripts/gh_settings.py`:
  - `normalize_ruleset(raw: dict) -> dict` — keep only the `<ruleset>` keys; sort `rules` by `type`; drop `parameters: null`; raise `SettingsError("admin view required: bypass_actors missing")` if `bypass_actors` absent.
  - `diff(expected: dict, live: dict) -> list[str]` — dotted-path lines, e.g. `rulesets.main.bypass_actors: expected [] got [...]`, `rulesets.merge-gate: missing`, `rulesets.foo: not in settings.json`, `labels.ai-review: missing`. Labels/collaborators/environments compare only the keys settings.json names (extra GitHub default labels are fine; extra collaborators are not).
  - `fetch_live(repo: str, gh=run_gh) -> dict` — same shape as settings.json; `run_gh(args: list[str]) -> object` wraps `subprocess.run(["gh", "api", ...])`, raises `SettingsError` on non-zero exit or bad JSON.
  - CLI: `gh_settings.py check [--repo omunite215/Project_SecondLine]` → prints `OK` or the diff lines, exit 0/1; `SettingsError` → message, exit 1. `gh_settings.py apply [--yes]` → without `--yes` prints the `gh api` calls it would make and exits 0 having made only GETs; with `--yes` POSTs missing rulesets, PUTs differing ones, creates missing labels. Never touches collaborators, secrets or environments (printed as manual steps).
