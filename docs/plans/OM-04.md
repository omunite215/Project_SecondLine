# OM-04 Ledger Reads, Scenario Loader, Namespaces, Export & State Hash — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a WorldBundle into a fresh namespace with one idempotent admin call, serve every §10 read tool from that namespace (as-of state version, record versions, provenance), and produce a canonical export whose sha256 is the same on every load and on every machine.

**Architecture:**
- An admin API (`/admin/v1/…`, harness only) creates namespaces and loads bundles. Each bundle goes through `BundleGuard`: schema check, a truth-field and canary scan, cross-reference checks. Then `WorldBundleLoader` writes it in **one** transaction at ns `state_version = 0`.
- An internal read API (`/internal/v1/ns/{ns}/…`, gateway only) answers the 11 read tools. The answers come from the relational tables plus typed projections of evidence records.
- `NamespaceExporter` builds the `ns_export` document. `StateHash` is the sha256 of its JCS form with `ns` removed.
- A BEFORE INSERT trigger stamps each ledger entry's `committed_version` from `namespaces.state_version`. That is what makes as-of reads possible, and the app can't forge it.

**Tech Stack:** OM-03's stack (Java 21, Spring Boot 3.5.16, Flyway, Postgres 17.11, Testcontainers, jqwik), Spring MVC, and the `libs/contracts-java` from OM-02 (`SchemaRegistry.validate(target, JsonNode)`, `CanonicalJson.canonicalize`, `Digests.sha256Canonical`, `ErrorCode`).

**Spec:**
- **Card and design:** card `python3 scripts/board.py show OM-04`; ADR-015 (namespaces, truth isolation, state hash); ADR-016 + `docs/domain.md` (accounts, precision); ADR-017 (evidence kinds, citations); ADR-019 (role model).
- **Spec shards:** §5, §9, §10 (read-tool table), §12.
- **Contracts:** `packages/contracts/scenario/{world_bundle,ns_export,truth}.schema.json`, `tools/*.output.schema.json`, `openapi/ledger-{internal,admin}.yaml`.

**Branch:** `om/OM-04-ledger-reads`, cut from `main` once #32 (OM-02) and #35 (OM-03) are merged. If #35 is still open, stack the branch on `om/OM-03-ledger-core` and rebase after the merge.

## Decisions (taken 2026-10-31, Om delegated; D1–D5 still need Kunal's approval on the contracts PR)
- **D2 is reversed: no new error code.** `tests/kit/test_sh_02_errors.py` pins `errors.json` to exactly §8's 12 codes, so adding one would depart from the spec. Instead, any id that can't be resolved in the caller's ns (an unknown or retired ns, a record that doesn't exist, a record in another ns) → `PERMISSION_DENIED` (403, "doesn't allow this … scope or run"). The answer is the same in every case, so no response leaks whether something exists, which also fits ADR-015's check of token ns against path ns. Every "not found" case below answers `PERMISSION_DENIED`.
- **D1 and D3–D6 are accepted as recommended.** Evidence checked:
  - D1: §5 lists `Counterparty(LEI/BIC?)` as a domain entity, and `ledger.trades.counterparty_id` is NOT NULL with an FK. KG-03 hasn't started, so this is the cheapest moment to change the WorldBundle.
  - D3: `ns_export` requires `ns`, and ADR-015 creates a fresh ns per run.
  - D5: the enums differ, as shown in the table.
- **Execution: native, with gated reviews.** The tasks are strictly sequential, and every task runs Testcontainers, so parallel subagents would break the 10 GB WSL cap. Reviews run at the boundary points: `contract-guardian` after Task 1, `leakage-auditor` after Tasks 3 and 6, and one whole-branch review before `/open-pr`.
- **Task 1 gets its own branch, `om/OM-04-contracts-2-0-0`, cut from `main`.** It doesn't depend on OM-03, so it can go to Kunal now. The code branch `om/OM-04-ledger-reads` stacks on `om/OM-03-ledger-core` until #35 merges.

Ledger-internal choices this plan makes on its own (Om's area, no contract change):
- **Evidence-backed reads.** `read_settlement_status`, `read_custodian_statement` and `read_corporate_actions` read typed projections (`settlement_events`, `custodian_records`, `corporate_actions`). The loader fills them from `SETTLEMENT_STATUS`, `CUSTODIAN_STATEMENT` and `CA_NOTICE` evidence. Each projection row reuses the evidence `record_id` and `version`, so what the agent reads is exactly what it cites (ADR-017).
- **Booking ids.** `journal_headers.entry_id` stays a uuid. A new `ref ledger.oid` column, `UNIQUE (ns, ref)`, holds the bundle's opaque `entry_id`. `read_bookings` returns `ref` as `entry_id`, because an `evidence_ref.record_id` must be an `opaque_id`.
- **Cost per ISIN** (`read_positions.cost`) = Σ(1300 D − C) over entries whose `trade_id` resolves to that ISIN. `currency` is the instrument's currency. Cash entries without a `trade_id` aren't attributed; Review Focus 4 covers this.
- **Zero balances.** The export leaves out zero balances, as `ns_export_minimal.json` does (4100-USD is declared but absent).

## Global Constraints
- **Inherits OM-03's constraints:** money, quantity, price and FX domains; "rejected, never rounded"; `(ns, id)` keys; immutable ledgers; typed `LedgerException(ErrorCode)`.
- **Truth isolation:**
  - No truth column, truth field name, `truth_ref` or `SLCANARY-` string is ever stored or returned.
  - The truth key set is read at startup from `packages/contracts/scenario/truth.schema.json`: every property name at any depth, plus `truth_ref` and `canary`. It is never hand-copied.
- **Load atomicity:** a bundle loads into **one** DB transaction. Any rejection leaves no `namespaces` row and no data rows.
- **Idempotency:** `snapshot_id` = `Digests.sha256Canonical(bundle)`.
  - Same ns + same snapshot → `200`, with the existing state hash and no writes.
  - Same ns + different snapshot → `STATE_CONFLICT`.
- **Canonical export:**
  - Cash balances are signed (debit positive) and rendered at the currency's minor-unit scale (JPY 0, others 2). Quantities are integers.
  - Arrays are sorted by `account`, then `currency` or `isin`.
  - State hash = `Digests.sha256Canonical(export minus "ns")` (D3).
- **Network exposure:** `/admin/**` and `/internal/**` are never published on a host port in compose. Authentication arrives in OM-07, so until then the network is the only guard.
- **Naming:** tests are `T_EVAL_03_…`, `T_DOM_03_…` and `OM_04_…`. Commits are `OM-04 §5 §9 §12: …`. Use `make test-ledger` only, within the laptop limits.

## Review Focus
1. **A truth key nested deep or with odd casing** (`breaks[0].fields.root_cause`, a top-level `truth_ref`, `"Root_Cause"`) → rejected, nothing written. The schema's `additionalProperties:false` catches most of these. The guard is the second layer for when the schema loosens. Pinned in Task 3: `T_DOM_03_truthKeyAnywhereRejected` (parameterised over every truth key, at the top level, in a trade and in evidence `fields`).
2. **Two loads of the same bundle into two namespaces, on two machines** → identical state hash. Pinned in Task 5: `T_EVAL_03_minimalBundleGoldenHash` (the hash is a committed constant), plus Kunal running `make test-ledger` on his Mac.
3. **Reading as of a version above the current one, or below 0** → `DOMAIN_INVALID`, never a silent clamp. Pinned in Task 6: `OM_04_asOfFutureVersionRejected`.
4. **Cost for an ISIN when cash entries carry no `trade_id`** → the cost excludes them, and the export (balances only) is unaffected. Pinned in Task 6: `OM_04_costIgnoresUnattributedEntries`. Keep the decision visible in the `read_positions` javadoc.
5. **A retired ns, or ns A's path given a record id from ns B** → `PERMISSION_DENIED`, never the other namespace's data. Pinned in Task 6: `OM_04_crossNamespaceReadIsDenied`, and in Task 7: `OM_04_retiredNamespaceIsDenied`.
