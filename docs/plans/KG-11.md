# KG-11 Supervisor: async monitors & kill switch — Implementation Plan

**Goal:** `services/supervisor` consumes ledger events. It dedupes by `event_id`, keeps state per run, and evaluates the detective invariants I9–I12. It alerts **once per state change** (fixing the PoC's repeat-alert defect), and on an alarm it halts *future* actions of that run and writes an incident record. It never undoes a commit (golden rule 1, ADR-004).

**Spec:** card KG-11 · §8 (invariant classes; detective vs preventative) · §12 (envelope, ordering per key) · §7 · REQ-008 REQ-010 · T-SEC-03 T-SWE-03 · I9 I10 I11 I12 · MET-10 · F5 F7 · ADR-004 ADR-014 (monitor and full conditions only).

**Branch:** `kunal/KG-11-supervisor`, stacked on #14 (KG-01).

## Decisions (P1; Kunal chose "read from ledger API")
| # | question | decision |
|---|---|---|
| S1 | The envelope has no payload (only `payload_hash`), so where do amounts come from? | A `LedgerReader` port: `transaction_lines(run_id, transaction_id)`. **Gap:** neither the main contracts nor 2.0.0 (#37) has a read-transaction or account-balance endpoint, so Om needs to add one (e.g. `GET /internal/v1/ns/{ns}/transactions/{id}`). Until then tests use a fake. Only I9 needs it. |
| S2 | Event types | The monitors key on a small closed set (`EVENT_TYPES` in `events.py`): `ledger.adjustment_posted`, `ledger.booking_corrected`, `ledger.corporate_action_applied`, `ledger.break_classified`, `ledger.break_escalated`, `ledger.break_closed`. Om's OM-13 outbox must emit these names or tell me the real ones. |
| S3 | I9 suspense growth | An agent (actor `agt_*`) may never post to 1900 (ADR-016), so **any** 1900 line in an agent-attributed transaction is a violation. The threshold is 0. It's policy, not tuned. |
| S4 | I10 transitions (per break = `aggregate_id`) | Violations: a mutation after the break was escalated or closed; a close with no prior mutation or classification; a classification after a mutation (reclassifying to hide an amount, §15 family 1). |
| S5 | I11 freshness | `committed_at − occurred_at` greater than `MAX_COMMIT_LAG_S`, or `committed_at` going backwards within one aggregate. The lag value is a **placeholder (60 s) to be tuned on dev only and frozen before KG-18**. |
| S6 | I12 audit sequence | Per `aggregate_id`, `aggregate_version` must be exactly previous + 1. A gap is a violation, and so is a fork (the same version under a different `event_id`). A replayed `event_id` is a duplicate: skipped, not an alarm. |
| S7 | Halting | Every alarm halts the run, through a `HaltSink` port (Redis flag + OM-12 `:halt`; neither is in the contracts yet, so tests use a recording sink). It halts only in the `monitor` and `full` conditions (ADR-014). It halts at most once per run, and every alarm writes an incident record. |
| S8 | Sources | JSONL now (the card says to develop on sample events). The Kafka adapter (library pinned once) comes with OM-13 integration, so no untested broker code ships here. |
