# SH-02 Contracts v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `packages/contracts` v1.0.0: JSON Schemas for every §10 tool, the action/receipt/approval/event shapes, errors.json and OpenAPI skeletons, each with valid examples, checked by `make contracts-check` in CI and tagged `contracts-v1.0.0` once both approve.

**Architecture:** Schemas are data (JSON Schema 2020-12, OpenAPI 3.1), validated by one stdlib-plus-`jsonschema` script. Shared building blocks (`$defs` in `common.schema.json`: decimal string, currency, account code, evidence_ref, ids) are referenced by `$ref` so money rules exist once. Om drafts everything below the tool boundary (tools, actions, receipts, approvals, events, errors, gateway/ledger/review OpenAPI); Kunal drafts scenario/truth/attack shapes and the eval OpenAPI (Task 6).

**Tech Stack:** JSON Schema 2020-12, OpenAPI 3.1, Python 3.12 + `jsonschema==4.26.0` (run via `uv run --with`, no repo pyproject until KG-01), GitHub Actions.

**Spec:** card SH-02 (`python3 scripts/board.py show SH-02`), §8 (protocol, error codes), §9 (canonical contracts draft), §10 (tool catalog), §12 (envelope), REQ-004/005/007, ADR-005, ADR-011, ADR-013, ADR-015, ADR-016 (accounting values), U3, U10, `.claude/rules/contracts.md`, `packages/contracts/CLAUDE.md`.

**Starts after:** SH-01 (#6) merged. Consumes ADR-016 (#10) values; if #10 changes them before merge, the affected enums change with it (minor bump only before the v1.0.0 tag).

## Decisions — the spec's inconsistencies, resolved (both owners confirm at plan review)

| # | spec conflict | decision |
|---|---|---|
| C1 | OPA `allow\|deny\|requires_review` (§8.3) vs receipt `ALLOW\|DENY\|REVIEW_REQUIRED\|EXECUTED` (§9) | contracts use the §9 upper-case set; OPA's lower-case output is internal to the gateway, which maps it. `EXECUTED` = ledger committed. |
| C2 | receipt `evidence_validation: VALID\|INVALID\|INSUFFICIENT` vs §8 `INSUFFICIENT_EVIDENCE` | `VALID \| EVIDENCE_STALE \| INSUFFICIENT_EVIDENCE \| INVALID` — the failing values *are* errors.json codes. |
| C3 | §8.2 validates request id, amount, scope, budget, deadline; §9 ProposedAction has none | ProposedAction gains `request_id`. Amount/currency/account live in type-specific `parameters`. Scope, budget and deadline are **server-derived** from the run token, never client fields (contracts rule: servers derive authority-bearing fields). |
| C4 | §9 `type: CLASSIFY_TIMING` matches no §10 tool; no type/reason enums | `type` ∈ {`CLASSIFY`, `BOOKING_CORRECTION`, `CORPORATE_ACTION`, `ADJUSTMENT`, `ESCALATE`}, one per §10 write tool; the classification goes in `parameters.classification`. `reason_code` enum from B1–B8 (list in Task 3), **Kunal confirms** (grader uses it). |
| C5 | §12 `transaction_id`/`policy_decision_id` vs §9 `ledger_transaction_id`, no decision id | both shapes use `ledger_transaction_id` and `policy_decision_id`. |
| C6 | §9 idempotency bound to actor/operation/payload but the constraint lacks a payload column | `UNIQUE(actor_scope, operation_type, idempotency_key)` + stored `action_digest`; same key + same digest → prior result, different digest → `IDEMPOTENCY_CONFLICT`. `action_digest = "sha256:" + hex(sha256(JCS(action without agent_explanation)))` — the untrusted narrative can't change authority (ADR-011). |
| C7 | versions all "1.0" while U10 is open | one API v1 (U10 resolved: the legacy v1/v2 deprecation demo is skipped; archived runs replay against the `contracts-vX` tag in their manifest). `$id` = `https://secondline.invalid/contracts/1/<path>`; `schema_version: "1.0"` fields stay; VERSION file is semver. |
| C8 | U3: no MCP pin | ADR-013 pins Python `mcp==2.3.0` and spec revision `2026-07-28` (both current on 2026-10-29); transport `stdio` for the local agent, Streamable HTTP only behind the gateway token (OM-06 VERIFY). |
| C9 | receipt signature optional; profile open (U9) | `signature_key_id` + `signature` optional in v1; profile left to ADR-018 (SH-09). |

## Global Constraints

- Money, quantity, price, FX: **decimal strings** via `common.schema.json#/$defs/decimal` (`^-?(0|[1-9][0-9]*)(\.[0-9]+)?$`); JSON `number` is forbidden for any of them (golden rule 3). Currency enum and account codes come from ADR-016 / docs/domain.md.
- Every schema: `"$schema": "https://json-schema.org/draft/2020-12/schema"`, versioned `$id` (C7), `additionalProperties: false` on objects, short `description`s (LLM-facing text lives in services/mcp-adapter/descriptions/).
- Error codes only from errors.json; `ORACLE_MISMATCH` is `grader_only: true`.
- No truth field (`truth_ref`, root cause, `expected_state_delta`, `SLCANARY-`) in any tool output, action, receipt, event or gateway/ledger/review OpenAPI (golden rule 4). Truth shapes carry `"x-privileged": true`.
- Synthetic only: examples use `.invalid` domains, opaque ids, fictional ISINs from a reserved prefix (`XS0000…`), no real names/accounts.
- Tests: `tests/kit/test_sh_02_*.py` (`test_SH_02_*`), stdlib; `scripts/contracts_check.py` is what CI runs.
- Branch `om/SH-02-contracts-v1`; commits `SH-02 §9 §10: …`; contract rule: bump VERSION, examples, `/handoff`, both approve.

## Review Focus

1. **A float sneaks into money** (`"amount": 10.5`, or a schema with `type: number`) → rejected. Pinned by `test_SH_02_no_number_type_for_money` (meta-check over all schemas) and a negative example per money-bearing schema (Task 1/3).
2. **Truth leaks into an agent-visible shape** (a `truth_ref` or `root_cause` property in a tool output) → contracts-check fails. Pinned by `test_SH_02_no_truth_fields_outside_privileged` (Task 1).
3. **Client sends authority fields** (`requires_approval`, `budget`, `approved_by` in ProposedAction) → schema rejects (`additionalProperties: false`). Pinned by `test_SH_02_proposed_action_rejects_authority_fields` (Task 3).
4. **Same idempotency key, reworded explanation** → same digest (retry is safe); different amount → different digest. Pinned by `test_SH_02_digest_ignores_explanation` (Task 3; digest computed in the test with a stdlib JCS for the example subset; OM-02 owns the real implementation and SH-08 the vectors).
5. **An example drifts from its schema** after an edit → CI red. Pinned by contracts-check validating every `examples/**` file against the schema named in its `$schema`-sibling `"x-validates"` key (Task 1).

### Task 3: action, approval, receipt, event

**Files:** Create `actions/proposed_action.schema.json`, `actions/parameters/{classify,booking_correction,corporate_action,adjustment,escalate}.schema.json`, `approvals/{approval_request,approval_decision}.schema.json`, `receipts/decision_receipt.schema.json`, `events/envelope.schema.json`, examples (valid + `invalid/`) for each; Test `tests/kit/test_sh_02_shapes.py`.

**Interfaces:**
- ProposedAction (§9 + C3/C4): `action_id, run_id, break_id, request_id, tool_schema_version, type, reason_code, parameters (oneOf by type), evidence_refs[≥1 except ESCALATE], expected_state_version, idempotency_key, agent_explanation (≤4000 chars)`.
- `reason_code` enum (C4, **Kunal confirms**): `CUTOFF_TIMING, PARTIAL_SETTLEMENT, QUANTITY_MISMATCH, ROUNDING_DIFFERENCE, PRICE_MISMATCH, FX_RATE_SOURCE, MISSING_TRADE, DUPLICATE_TRADE, CORPORATE_ACTION_SPLIT, CORPORATE_ACTION_OTHER, CASH_SHORTFALL, SSI_MISMATCH, INSUFFICIENT_EVIDENCE, OTHER_ESCALATION`.
- `adjustment` parameters (§10: currency, amount, account, affected trade, purpose, versions): `currency, amount (decimal), debit_account, credit_account (cash_account; 1900 allowed by schema, forbidden by OM-08 validator — policy, not shape), trade_id, purpose (enum ROUNDING|FX_REVALUATION)`.
- `booking_correction`: `trade_id, isin, corrected_quantity (decimal, scale 0), corrected_price (decimal)`; `corporate_action`: `ca_event_id, isin, ratio_numerator, ratio_denominator (integers ≥ 1)`; `classify`: `classification` enum (TIMING, PARTIAL_SETTLEMENT, NO_BREAK); `escalate`: `queue` enum (OPERATIONS, REFERENCE_DATA, TREASURY).
- ApprovalRequest: `approval_id, action_digest, action_id, evidence_versions[], state_version, requested_at, expires_at, maker_id`; ApprovalDecision: `approval_id, action_digest, checker_id, decision (APPROVE|REJECT), reason_code, decided_at` (maker ≠ checker is a server check, documented in `description`).
- DecisionReceipt (§9 + C1/C2/C5/C9): `receipt_version, receipt_id, action_id, action_digest, decision, policy_decision_id, policy_bundle_hash, evidence_validation, error_code?, approval_id?, ledger_transaction_id?, previous_receipt_hash, receipt_hash, signature_key_id?, signature?, issued_at`.
- Envelope: the 19 §12 fields verbatim, `payload_hash`/`evidence_hashes` as `sha256_ref`, `redaction_class` enum (PUBLIC, INTERNAL, RESTRICTED).
