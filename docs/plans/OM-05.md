# OM-05 Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **`learn` card, learn_mode on:** the steps marked **[Om writes]** are Om's. Claude writes the failing tests that define them first, then reviews and hardens Om's code. It never writes those bodies.

**Goal:** `services/gateway` is the policy enforcement point.
- `POST /v1/runs` issues a short-lived Ed25519 run token bound to run + ns.
- `POST /v1/runs/{runId}/tools/{tool}` runs token → run binding → schema → budget/halt → OPA (full controls only) → ledger (service JWT) and returns a typed result.
- Every decision, denies included, is persisted. A write fails closed when OPA or the ledger can't answer.

**Architecture:** one Spring MVC controller over a `ToolPipeline` whose stages are small interfaces (`RunTokens`, `InputSchemas`, `RunGuard`, `PolicyClient`, `LedgerClient`, `DecisionLog`), so each stage is unit-testable and a stub in the others' tests. Tool → ledger routing is table-driven from `tools/INDEX.json` (risk `read` → GET route; `high`/`restricted` → `POST /internal/v1/ns/{ns}/actions` with the body unchanged, because write-tool inputs *are* `ProposedAction`s and outputs *are* `DecisionReceipt`s).

**Tech Stack:**
- Java 21, Spring Boot 3.5.16 (web, actuator), libs/contracts-java (SchemaRegistry, ErrorCode, ErrorResponse, Contracts.MAPPER).
- Nimbus JOSE+JWT, with Google Tink for Ed25519 (OKP).
- Micrometer, plus `micrometer-tracing-bridge-otel` for the span.
- OkHttp `mockwebserver3` to stub the ledger and OPA in tests.
- Versions are pinned in `gradle/libs.versions.toml`, at least two weeks old (VERIFY at Task 1).

**Spec:**
- card: `python3 scripts/board.py show OM-05`;
- §7 §8 (steps 2–3, error semantics) §10 §11 (identity scheme, SEC-03, SEC-13, fail-safe defaults);
- ADR-013 (pipeline order, run_id from token), ADR-014 (what each condition switches on), ADR-015 (ns binding), ADR-005;

## Decisions (proposed; Om approves this plan before Task 1)
| # | Question | Decision | Why |
|---|---|---|---|
| G1 | JWT library | Nimbus JOSE+JWT + Tink (`Ed25519Signer`/`Ed25519Verifier`). No hand-rolled JWS. | Battle-tested alg/header handling; JDK EdDSA alone would mean writing JWS parsing ourselves (insecure-defaults). ADR-018 receipts stay on JDK EdDSA: a different artefact. |
| G2 | Run-token claims | `iss=secondline-gateway`, `aud=secondline-gateway-tools`, `sub=<agent_id>`, `run_id`, `ns`, `scenario_id`, `allowed_tools[]`, `controls`, `iat`, `nbf`, `exp`, `jti`. Header `alg=EdDSA`, `kid`. TTL `gateway.run-token.ttl` (default 30 min; the run's wall-clock cap, SEC-13). | §11 identity scheme; ADR-013. `allowed_tools` = every §10 tool in every condition (ADR-014: same surface). |
| G3 | Verification | Reject unless all of: `alg` is exactly `EdDSA`; `kid` known; signature; `iss`; `aud`; `exp`/`nbf` with ≤ 30 s skew; `run_id` claim = path `runId`; tool ∈ `allowed_tools`; body `run_id` = token `run_id`. Every failure → 403 `PERMISSION_DENIED` with the same message. | Fail closed (rule 7); one answer for every token failure, so it isn't an oracle. |
| G4 | Keys | Ed25519 private JWK from a file (`GATEWAY_SIGNING_KEY_FILE`, under `secrets/`, created by `make bootstrap`). A missing or unreadable key → the gateway refuses to start. Only the public half is ever logged or exported. | Secrets never in git or env values (OM-15); fail fast. |
| G5 | `POST /v1/runs` auth | `Authorization: Bearer <GATEWAY_OPERATOR_TOKEN>` (≥ 32 random bytes from `make bootstrap`, constant-time compare). Unset → every run creation denied. | The card says "operator auth". The realm design is OM-07's ADR, and this is the minimum that fails closed until then. |
| G6 | Run creation | Validate `run_request` → ledger `POST /admin/v1/runs` (ns must be LOADED, or 403) → token. `Idempotency-Key`: the same key + the same body digest → the same token. A different body → 409 `IDEMPOTENCY_CONFLICT`. The store is in memory and bounded; a gateway restart forgets keys, which is a documented limit. | gateway-tools.yaml; there's no gateway DB in v1. |
| G7 | Contract gap: run_request has no `scenario_id` or `manifest_ref` | contracts **2.1.0** adds both to `runs/run_request.schema.json`, both required. | The token needs `scenario_id` (G2) and the ledger registry needs `manifest_ref` (OM-04). Kunal's runner sends them. |
| G8 | Contract gap: decision log | contracts 2.1.0 adds `POST /internal/v1/ns/{ns}/decisions` with `runs/decision_log_entry.schema.json`: `{decision_id, run_id, tool, action_id?, decision: ALLOW\|DENY\|REVIEW_REQUIRED, error_code?, controls, policy_bundle_hash?, stage, at}`. The ledger stores it append-only (V006 `policy_decisions`, no UPDATE/DELETE). | Card: "every decision incl. denies persisted via ledger". `stage` names where a deny came from (token, binding, schema, guard, policy, ledger). |
| G9 | OPA | Called only when `controls=full` and the tool's risk ≠ `read`: `POST {opa}/v1/data/secondline/decision` with input `{run, tool, action}` → `{decision, reason, bundle_hash}`. A timeout of 200 ms, an error or an unparsable answer → `RETRYABLE_UNAVAILABLE` (503) and no ledger call. OM-10 writes the Rego; OM-05 tests stub OPA. | ADR-014 (off/monitor never call OPA); §11 fail-safe. |
| G10 | Budget/halt | `RunGuard` interface. OM-05 ships an in-memory implementation: per-run tool-call cap (`gateway.budget.max-calls`, generous, harness safety) + a halted-runs set. → `RUN_HALTED` (423). OM-12 replaces it with the ledger-backed halt flags. | ADR-014: budgets are on in every condition. |
| G11 | Ledger unreachable | Reads and writes → `RETRYABLE_UNAVAILABLE` (503). Ledger 4xx error bodies pass through unchanged (they are already contract `error_response`s). | Fail closed; no gateway-invented outcomes. |
| G12 | Service JWT to the ledger | The gateway signs a 60 s service JWT (`aud=ledger`, `sub=gateway`) per call with its own key. The ledger verifies it in OM-07. | Card; ADR-013. |
| G13 | Measurement | `gateway.onpath` Timer with a percentile histogram and SLO buckets of 1, 2, 5, 10, 20, 50, 100, 200, 500 ms, from request in to response out, excluding the MCP hop (ADR-013). `OM_05_OnPathBench` makes 2,000 calls against stubbed ledger/OPA, writes p50/p95/p99 to `build/reports/om05-onpath.json`, and labels them **SIMULATED (stubbed dependencies)**. | Card: "logged locally (measured, not claimed)". |

## Global Constraints
- Errors only from the contracts `ErrorCode`, as `error_response` bodies serialised via `Contracts.MAPPER` (no null fields). A message never echoes a request value or a token.
- Never log a token, key or operator secret. Log run_id and action_id only.
- Test names `OM_05_…`, `T_SEC_02_…`; commits `OM-05 §8 §11: …`. Laptop limits: `-Xmx512m`, Gradle workers ≤ 4, targeted test runs.
- No change to OM-04 ledger behaviour except V006 + the decisions endpoint.

## Review Focus
1. **`alg` confusion:** a token with `alg: none`, `HS256` keyed with the public key, or an unknown `kid` → 403. Pinned by `OM_05_tokenAlgorithmConfusionRejected` (Task 2).
2. **Run swap:** run A's token on run B's path, or a body `run_id` = B under A's token → 403, and nothing logged as ALLOW for B. Pinned by `T_SEC_02_runBindingEnforced` (Task 4).
3. **OPA down in full controls** → 503 `RETRYABLE_UNAVAILABLE`, the ledger is never called (MockWebServer request count 0), and the decision is logged as DENY with `stage=policy`. Pinned by `OM_05_opaDownFailsClosed` (Task 4).
4. **A denied call changes nothing.** The ledger state hash is identical before and after. Pinned by `OM_05_deniedCallLeavesStateHash` (Task 6), an integration test against the real OM-04 ledger.
5. **Clock skew and expiry:** `exp` 31 s in the past → 403; 29 s → accepted. Pinned by `OM_05_expiryWithSkew` (Task 2).
