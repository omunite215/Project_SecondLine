# OM-03 Ledger Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The ledger's persistent core: namespaced tables, two double-entry ledgers (cash per currency, securities per ISIN) with DB-enforced balance and immutability, reversals, and a position projection. All of it is property-tested.

**Architecture:**
- Flyway migrations create every table keyed `(ns, id)`.
- They run as a separate owner role, `ledger_migrator`, from a one-shot compose service. The running ledger (`ledger_svc`) gets DML only, and no UPDATE/DELETE on the ledgers (ADR-019).
- `CashPostingService` and `SecuritiesPostingService` validate in Java, and a deferred constraint trigger re-checks balance at commit.
- Positions are a projection, recomputed from the securities ledger and maintained incrementally in the same transaction.

**Tech Stack:** Java 21, Spring Boot 3.5.16 (BOM: Flyway 11.7.2, PostgreSQL JDBC 42.7.11, Testcontainers 1.21.4), Postgres `17.11-alpine` (same as compose), jqwik 1.10.2, ArchUnit 1.5.1.

**Spec:**
- card: `python3 scripts/board.py show OM-03`;
- ADR-016 and **docs/domain.md**, which holds the chart of accounts, precision and posting patterns, and is authoritative for every number below;
- ADR-015 (namespaces); §5 §9 shards; `.claude/rules/migrations.md`, `.claude/rules/money.md`;
- `infra/db/init/00-roles.sql`.

## Decision (Om, 2026-10-30): separate migrator role
- **Why:** if Flyway ran as the app, `ledger_app` would own the tables, and a buggy or compromised ledger could `ALTER TABLE … DISABLE TRIGGER` or `DROP SCHEMA ledger CASCADE`. T-DOM-05 would then only prove that a trigger exists.
- **Roles:**
  - `ledger_migrator` (a new LOGIN) owns schema `ledger` and every table.
  - `ledger_app` gets SELECT/INSERT on the ledgers, and SELECT/INSERT/UPDATE only on mutable read models such as `breaks.state_version` and `positions`.
- **Where Flyway runs:** in a one-shot compose service `ledger-migrate`, the same image with profile `migrate`, `web-application-type=none`, and the migrator secret. `ledger` waits on `service_completed_successfully` and never holds the migrator password.
- **ADR:** recorded as ADR-019 (PROPOSED in Task 1). It touches OM-01 infra, which is in Om's area.

## Global Constraints
- **Money:** `NUMERIC(24,6)` plus `CHAR(3)` currency, and Java `BigDecimal` only. A posted amount's scale must be ≤ the currency's minor units (USD/EUR/GBP/CHF 2, JPY 0). A higher scale is **rejected, never rounded**.
- **Other numerics:** quantity `NUMERIC(20,0)` and > 0, price `NUMERIC(24,8)` and > 0, FX rate `NUMERIC(24,10)` with `rate_source`, `as_of` and `rate_id`.
- **Currency set:** exactly {USD, EUR, GBP, CHF, JPY} (ADR-016 (a)).
- **Accounts:**
  - cash `1110 1210 1300 1500 1900 2100 4100 4200 4300`, always paired with a currency;
  - securities `S100 S200 S900`, always paired with an ISIN.
- **Keys and immutability:** every table carries `ns uuid`, and its PK starts with `ns`. Composite FKs `(ns, x_id)` are used, so no cross-namespace reference is possible.
  - Committed ledger rows are never updated or deleted. A correction is a full negating entry with `reverses_entry_id`, followed by a rebook. No partial reversal, and at most one reversal per entry.
  - Quantity and position changes go only to the securities ledger, never as cash entries.
- **Typed errors:** domain errors throw `LedgerException(ErrorCode)` with codes from `com.secondline.contracts.generated.ErrorCode` (#32). Use `DOMAIN_INVALID` for validation failures, unless a task names another code.
- **Naming:** test names are `T_DOM_01_…`, `T_DOM_05_…`, `OM_03_…`. Commits are `OM-03 §5 §9: …`.
- **Laptop limits:** one singleton Postgres Testcontainer per test JVM, `-Xmx512m`, Gradle workers ≤ 4. Use `make test-ledger`.
- **Prerequisite for Task 5:** #32 (OM-02) merged and this branch rebased. Tasks 1–4 don't need it.

## Review Focus
1. **Scale above minor units** (`"1.5"` JPY, `"0.001"` USD, `"10.10"` stays valid for USD) → `DOMAIN_INVALID`, not rounded. Pinned in Task 4 `OM_03_money_rejects_scale_above_minor_units` and Task 5 `T_DOM_01_scaleAboveMinorUnitsRejected`.
2. **Reversing twice, or reversing a reversal** → the second attempt is rejected by `UNIQUE (ns, reverses_entry_id)`. Pinned in Task 6 `T_DOM_05_secondReversalRejected`.
3. **Cross-namespace reference** (an entry in ns A reverses an entry in ns B) → FK violation, surfaced as `DOMAIN_INVALID`. Pinned in Task 6 `OM_03_reversalAcrossNamespacesRejected`.
4. **Unbalanced rows inserted with raw SQL, bypassing the service** → rejected at commit by the deferred trigger. Pinned in Task 3 `T_DOM_01_dbRejectsUnbalancedEntryAtCommit`.
5. **Currency or account outside the sets** (`usd`, `XXX`, `1900` without currency, `S100` on the cash ledger) → CHECK violation, or `DOMAIN_INVALID` from the service. Pinned in Task 3 `OM_03_accountAndCurrencyChecks` and Task 4.
